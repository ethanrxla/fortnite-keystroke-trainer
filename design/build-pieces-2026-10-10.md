# Build pieces as data (2026-10-10)

Every build piece and edit is now data in `shared/edits.json`, read by one small class hierarchy in Python
(`companion/keystroke_lab/build_pieces.py`) and its Verse twin (`verse/KeystrokeTrainer/BuildPieces.verse`).
This is handoff item 3 ("piece classes") and the data half of item 4 ("edits for the other pieces").

## Model

| Piece | Class | Grid | Unedited class | Edit semantics |
|---|---|---|---|---|
| wall | `WallPiece` / `kt_wall_piece` | 3 x 3 | `Solid` | selected tiles are cut out |
| floor | `FloorPiece` / `kt_floor_piece` | 2 x 2 | `Floor` | selected tiles are cut out |
| cone (roof) | `ConePiece` / `kt_cone_piece` | 2 x 2 | `RoofC` | selected tiles are cut out |
| ramp (stairs) | `StairPiece` / `kt_stair_piece` | 2 x 2 | `StairW` | the dragged path, bottom first, becomes the stairs |

- **Base class** (`BuildPiece` / `kt_build_piece`): material, health, grid cell, the edit selection, select / reset /
  confirm, and the one update function `visual()` / `Visual()` (visible tiles, colliding tiles, result class).
- **Edit state**: the selection in order. Walls, floors and cones compare it as a bitmask (sum of 2^tile, the
  "bool grid" view is `EditPattern.rows`). Ramps compare the ordered path, because the climb direction matters.
- **Pattern table**: every entry of `shared/edits.json` (suggested or not). Python reads the JSON; Verse reads
  `EditPatterns.verse`, generated by `tools/gen_edits.py`. A confirmed edit is valid only if it is in the table.
- **Rejection**: `nothing_left` (everything selected), `broken_path` (ramp step to a non-neighbour or a repeat),
  `floating` (kept tiles split into parts and the game has no class joining them; a door or a diagonal floor does),
  `unsupported_shape` (not in the table).

## Where the shapes come from

All 34 `PBWA_W1_*` classes in `/Game/Building/ActorBlueprints/Player/Wood/L1` were placed in UEFN far from the map,
photographed front-on and top-down (`design/build-class-probe/sheet-*.png`) and removed again. Each edit now has
`result_class` and `result_class_status` (`probe_matched`, `probe_inferred`, `unidentified`). What the pictures settled:

- Floors and cones: all 14 selections of each are real pieces (`Balcony`/`Roof` + I = 3 kept, S = 2 side by side,
  D = 2 diagonal, O = 1 kept). Which of I/O is one tile selected on a cone is inferred, VERIFY.
- Walls: window, door, side door, half and quarter wall, arch, half arch (`ArchwayLarge`), corners (`Brace` lower,
  `RoofWall` upper), side window, plus shapes the library lacked: double window `[3,5]` (`Windows`, the centre post
  stays, so the whole middle row is *not* that piece), door + side window (`DoorS`), half wall with centre or side door,
  pillar, slim half wall.
- Ramps: `StairW` full, `StairF` half ramp (2 tiles), `StairR` L ramp (3), `StairSpiral` (4). All 24 paths round the
  2 x 2 ring are in `stairs_edits` with a `path`. `StairT` was not matched to a path yet.

Nothing new is suggested and nothing is marked verified; shapes still go through the review and promotion pipeline
(`review-edits`, `tools/promote_edits.py`) before the guide or Jev's priors use them.

## In the map

`kt_edit_piece_device` is an editable practice piece made of one prop per tile (the "9 small squares" wall):
wire `TileProps` (tile order), optional `SelectMarkers` (blue highlight props), `TileButtons`, `ConfirmButton`,
`ResetButton`, and optionally `ResultIds` / `ResultProps` to swap in a finished-shape model. Hidden props also lose
collision. It logs `KT|piece_edit|<kind>|...|edit=<id>|valid=|reason=|class=`. Not placed in the level yet.
`AutoTest.verse` runs `KTBuildPieceTests` (BP01 to BP08) with the other logic tests.
